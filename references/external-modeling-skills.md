# 外部数学建模技能的取舍

本技能是唯一调用入口。以下四个作者原仓库仅作为已定位和审阅入口内容的参考来源；本次不把它们安装为额外技能，不直接迁入其源码，也未验证其整套脚本能运行。来源快照与入口文本哈希见 `external-skill-sources.json`。

| 原仓库 | 可借鉴的做法 | 本技能的适配与排除 |
| --- | --- | --- |
| [XiaoMaColtAI/math-modeling-skill](https://github.com/XiaoMaColtAI/math-modeling-skill) | 建模—实现—写作之间明确输入输出，单阶段按需执行 | 用本技能的问题映射、模型合同和结果登记实现交接；不强制固定图数或两种文档格式；本轮未核定其源码复用许可 |
| [Hjdd14/math-modeling](https://github.com/Hjdd14/math-modeling) | 模型/数据/符号契约，小例验证，失败回到来源阶段 | 纳入模型合同和三级审核；不继承两次确认码、固定多 Agent 或大量固定文件要求 |
| [touhouZELDA/math-modeling-contest](https://github.com/touhouZELDA/math-modeling-contest) | 子问题依赖、旧结果失效、图与成品分层检查 | 保留依赖与变更追踪；不继承固定评委分数、字数页数、LaTeX-only 或通用固定扰动幅度 |
| [Zhengxuejun/mathematical-modeling-agent](https://github.com/Zhengxuejun/mathematical-modeling-agent) | 目标到报告的结构化交接、状态推进、结果冻结与失败模式 | 用轻量合同、真实运行记录和哈希实现；工程链路通过不等于正式模型正确；按题目决定敏感性范围 |

## 使用边界

1. 原仓库的自述不是效果验证，未用这些项目的自评分承诺获奖或科学正确。
2. 来源记录中的许可证信息来自 GitHub 仓库元数据，只标记观测到的值；未据此作完整法律审查。后续如复制代码，另核实际许可并保留通知。
3. 用户不需要切换四个 skill、手动维护台账或逐次确认普通流程。当前技能在授权范围内自动推进，只有真实缺失且会改变决策的信息才询问。
4. 模型、数据和符号合同按实际题目建立；模型库只能提供候选，不能代替题意与可行性判断。
5. 接入新组件时先读源码/依赖并运行针对性检查。只有文档存在不能宣称组件已安装或验证。

这些做法是独立整理后的工作流设计，不是源代码合并。所有建模结论仍服从本技能的来源、逻辑和未核验信息三级审核。
